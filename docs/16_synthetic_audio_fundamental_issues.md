# 合成音频根本性问题（第三轮 Review，2026-08-12）

## 核心发现：合成音频与 caption 不匹配

人工 review v2 音频后发现**合成音频无法支撑 caption 任务**。

### 问题 9：合成音色与描述文本完全不匹配（CRITICAL）
- **mix_002294**：caption 标注有 speech，但**完全听不到人声**
- **mix_003724**：同理，caption 有 speech 但无声音
- **mix_000767**：caption 标注歌词，但**听不到任何歌词**
- **mix_000693**：caption 标注"远处的犬吠"，但**听不到犬吠**

**根因**：`SyntheticSourcePool` 生成的"语音"是正弦波+包络，"人声"是带颤音的持续音，"音效"是噪声 burst。这些**不是真实的语音/人声/音效**，人耳无法辨认。

**影响**：模型在合成数据上学到的"语音→speech 标签"关联，在真实音频上可能完全不成立。

### 问题 10：caption 过于简单，缺乏语义丰富度
当前 caption 来自固定短语列表：
- speech: "一名说话者正在讲话。"
- music: "背景音乐持续播放，节奏平稳。"
- sfx: "短促的撞击声。" / "远处的犬吠。"
- vocal: '"take me home tonight"'

**缺失**：
- ? 声学环境描述（房间、混响、室内/室外）
- ? 音效详细描述（材质、力度、距离、持续时间）
- ? 音乐风格（流派、节奏、乐器、情绪）
- ? 说话人信息（性别、年龄、语速、情绪、口音）
- ? 说话内容（speech 的实际文字转录）
- ? 歌词内容（vocal 的实际歌词）
- ? 事件间关系（"玻璃声打断了说话"）

### 问题 11：音频种类有限 + 多样性不足
当前合成器只有 4 种基础波形：
- 语音：正弦波+formant+包络（不像真人声）
- 音乐：固定和弦进行 [220, 246.94, 196, 174.61] Hz（**所有 clip 听起来像同一首电子音乐**）
- 音效：噪声burst+衰减（不像真实音效）
- 环境：粉红噪声+调制（不像真实环境音）

**多样性问题**：
- 音乐源使用固定和弦序列，仅通过随机种子微调参数 → 听起来都是同一首
- 人声源是纯音+颤音 → **没有真实歌词**，无法产生可辨识的演唱
- 音效源是通用噪声burst → "犬吠""玻璃""撞击"听起来完全一样

### 问题 12：原始音源 caption 质量影响混合后训练数据
**发现**：当前合成音源的 caption 是从固定短语列表中随机选择的，与实际音频内容无关。如果后续接入真实音源：

1. **真实音源的原有标注可能简单**（如 Freesound 的 tag、LibriSpeech 的纯转录）
2. **需要对每个音源重新生成丰富 caption** 才能混合出高质量训练数据
3. **混合后的 caption = 各源 caption 的组合 + 声学环境 + 事件关系**

**建议流程**：
```
真实音源 → MOSS/LLM 逐源 caption（丰富描述）→ 混合 → 组合 caption → 训练数据
```

每个源的 caption 应包含：
- 声音描述（是什么声音、材质、力度、距离）
- 声学特征（频谱、节奏、持续时间）
- 对 speech：说话人特征 + 说话内容摘要
- 对 music：流派 + 节奏 + 乐器 + 情绪
- 对 vocal：歌词内容 + 演唱风格

混合后的 caption 再加上：
- 声学环境（房间大小、混响 T60、室内/室外）
- 事件间时序关系（"A 在 B 之前""A 被 B 打断"）
- 整体场景描述

## 根因分析

合成数据的根本矛盾：
```
caption 描述的是真实世界声音 → 但合成音频是数学波形 → 人耳无法辨认 → caption 失效
```

这意味着：
1. **模型在合成数据上的 F1=0.948 不代表真实场景能力**——它只是在学时间结构
2. **caption 质量受限于合成器的表达能力**——无法生成真实音色对应的丰富描述
3. **需要真实音频采样**——合成器无法替代
4. **需要对真实音源重新 caption**——原始标注不够丰富，需 LLM 增强

## 改进方案

### 方案 B：接入真实音效库（推荐，优先级最高）
1. **Freesound CC0**：分类音效（雨声、犬吠、玻璃、门响、脚步等）
2. **LibriSpeech**：真实人声+转录（用于 speech 源）
3. **MUSDB18**：真实音乐+分轨（用于 music/vocal 源）
4. **FMA dataset**：多样化音乐片段

`FileSourcePool` 已实现，只需配置路径即可切换。

### 方案 D：LLM 辅助逐源 caption 生成（与方案 B 配合）
```python
# 步骤 1：对每个真实音源生成丰富 caption
source_caption = llm_caption(audio_source, kind, conditions)
# → "一名年轻男性以中等语速说道：'今天的天气真好。'语气轻松。"

# 步骤 2：混合后组合 caption
mixed_caption = compose_captions(source_captions, conditions, relations)
# → "在小型室内空间中（T60=0.4s），一名男性说话者..."
```

### 方案 E：混合数据策略
| 数据源 | 比例 | 用途 |
|---|---|---|
| 真实音效（Freesound CC0） | 40% | sfx/ambience 源 |
| 真实人声（LibriSpeech） | 20% | speech 源 |
| 真实音乐（MUSDB18/FMA） | 20% | music/vocal 源 |
| 合成音频 | 20% | 补充多样性 + 控制实验 |

## 对论文的影响
1. **合成数据实验定位为"格式验证"**——证明模型能学格式和时间结构
2. **真实数据实验是论文的必要条件**——证明模型在真实场景有效
