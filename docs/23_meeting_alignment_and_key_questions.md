## 1. 纪要提炼出的研究思路（原始意图，未加评判）

### 1.1 任务定义
**为混合音频中的每一条音轨生成带精确时间戳的 caption。** 这与 `docs/02 §3` 的输出定义（事件集合 + 0.1 s span + 类型 + source id）、`docs/08 §1` 的中心命题（复杂音频 caption 的根本困难是 source attribution）完全同源。

### 1.2 双向价值论证（纪要独有、文档缺失）
- **反向（应用侧 / 讲故事维度）**：精准时间戳作为**下游生成的控制信号**——agentic 音频生成、多音轨精细混合、视频精确动作控制、精调数据的自动标注供给。定位是“万金油前置数据能力”，生成组 / 理解组 / 交互组都能用。
- **正向（问题侧）**：攻三大技术挑战——① 复杂场景处理 ② 精准时间戳 ③ 可解释性（**训练层 + 推理层双层**）。

### 1.3 分层定义（三层）
1. **场景**：只用于**规则设定与数据构造**，不作为模型输入；
2. **实体 / 轨**：需带“音源特色”等属性；
3. **事件**：需识别**跨时间复现的同一事件或同一说话人**，输出 ASR 等具体内容。

纪要明确承认：分层的目的是“指导数据构造”，动态时域变化（走近瀑布、室内走到室外）当前**搁置**。

### 1.4 数据路线
- 开源数据集 **recaption**（补情感等细节标签），弥补现有 caption 粒度过粗；
- 用已有时长/时间戳标签，**按真实逻辑拼接**不同音频（规则派 + LM 派两种策略）；
- 音频合成需调相位、噪声、淡入淡出、按隐私/场景动态调背景音量；刻意制造**密集重叠**造高难样本；
- 引入混元团队爬取的互联网数据（**无真实标签，全靠大模型打标**）；
- 承认三大瓶颈：源音质偏低、裁剪/ID 校验容错率极低、场景-音源合理性。

### 1.5 模型与训练路线
- 首选 **all-in-one 统一架构**（规避 agent 复杂性 + 降低对外宣讲被质疑的风险），退路是多个单功能模型 + agent 拼装，再退是 MoE；
- 把**层级定义为 query 来学习**（全局 query / 变长 query / 向量 query），目的之一是省 token；
- 训练先**纯 SFT + 文本 CE**，一切从简；
- 抑制幻觉用 **DPO**：构造“有 / 无特定音频”的成对数据做偏好学习；
- 复杂 loss 的核心难点是**有效性验证**，必须对每一类数据做消融；
- **可解释性第二层在推理层**：把解码后的 query 交给外部模型检测幻觉与逻辑错误（轨-事件不匹配）；细化为生成 **Clue / Claim + 0–1 置信度**，低置信触发二次校验。粗粒度校验（室内外声学环境）可行，细粒度暂无良策。

### 1.6 节奏
一个月周期 → **前两周全力攻数据**；先人工 review 小批量 → 确认无误后 **500 条在小模型上过拟合**；下周组会前完成规则梳理；数据集论文可拆分或合并发表。

### 2.2 纪要与已有实测证据冲突、必须纠偏的部分

这是本次分析最有价值的部分。以下 6 条如果按纪要原样推进，会重复踩已经踩过的坑。

**① “每一轨生成 caption” 不能实现为推理时的显式分轨级联**
`docs/13 §1` P5 topline 已实测：mixture 直接 caption **0.948** > oracle stems → MOSS **0.890** >> Demucs 分离级联 **0.270**（−70%）。
→ per-track 是**标注层与表示层**的组织方式（`docs/08 §2.2` 的 teacher explicit / student implicit），不是推理层的 pipeline。纪要中“先分轨、每轨交专家模型”只能存在于教师侧造数据。

**② “recaption 开源数据 + 规则/LM 拼接” 就是 TAC-style 合成，其分数已被自我否定**
`docs/16` 结论：合成集 F1 0.948 不代表真实能力（合成“语音”是正弦波、5000 条音乐共用同一组和弦）。
`MEMORY.md` 实测：**200 条真实音源 + 3000 步 (0.967) 已超过 5000 条合成 (0.948)**。
→ 拼接路线本身没错（`docs/03 §7.1` 就是可控变量表），但**素材必须是真实录音**，且合成集只能定位为“格式与时间结构验证”，不能作为主结果。

**③ “核心矛盾从‘数据够不够’转向‘怎么拼才合理’” 只说对了一半**
v6k 扩量实测（`MEMORY.md`）：1000 条真实数据把事件 F1 推到 0.970 后**饱和**，但细粒度指标**恶化**——±0.1 s 命中率 0.842 → **0.635**、onset MAE 0.178 → 0.262 s、pointer 0.30 → **0.34**、source_count MAE 0.95 → **1.14**。
数据结构诊断出 7 条硬缺口：
1. `events-per-track = {1: 2740}` → track↔event **100% 双射**，pointer 零训练信号，且输出格式**不含 track 字段**，0.34 既不可学也不是有效测量；
2. speech track 数 ∈ {0,1} → **零多说话人重叠**，恰是方案第一号难点；
3. **`lys` 事件 = 0**，歌词轨完全缺失；
4. `spans-per-event = {1: 2740}` → 无重复实例，SpotSound 指出的核心问题未被覆盖；
5. `conditions` / `audibility` / `boundary_uncertainty` **全空** → 分层评测与 CARC 可听性门控做不了；
6. music caption 含人声关键词 **196/566 = 34.6%**（GTZAN classical/jazz/blues 并非纯器乐），`docs/21` 的“音乐源问题已解决”结论**是错的**；
7. manifest 不记源文件路径，`scripts/eval_heldout.py:15` 按 `manifest[180:]` 索引切分 → 无法 group split、无法验证泄漏。
→ **正确表述是“结构 > 数量”**：加 5 倍数据对 0.1 s 精度与声源归属完全无效。纪要“数据充足、先扩规模”的判断需要改为“先修结构、暂不扩量”。

**④ “把层级定义为 query 来学习” 已经试过并失败**
`docs/13 §1` S1a：activity-mask / boundary-reg / joint-encoder 三版 F1 = 0.101 / 0.081 / 0.123，**连 32 条样本都无法过拟合**（DETR 优化困难）。
当前所谓 “slot-aware”（F1 0.926/0.948）**只是“输出前加一句事件计数”的廉价替代**，不是槽位解码器。
→ 纪要“query 省 token”“变长 query”若要推进，必须先申请大 batch + 辅助损失 + 500+ epochs 的优化基础设施预算（`docs/13 §7` 已把它列为**低优先级**）。论文里绝不可含糊表述为“slot decoder”。

**⑤ “互联网数据全靠大模型打标” 触发自我验证闭环风险**
纪要自己也点出“用模型打标再训练，上限易被锁死”。`docs/03 §1` 的原则是**把 teacher 输出当证据，不当真值**；`docs/03 §6` 要求“至少两个独立音频证据达标、视觉只能加权”。
当前 v6/v6k 的 `label_level = "model_prediction"` 且 teacher = 底座 = 评价三者**都是 MOSS 家族**。
→ 必须引入结构不同的验证信号：ASR 强制对齐、FLAM/开放词汇 SED、重构误差、反事实差分（`MEMORY.md` 长期警惕第一条）。

**⑥ “精准时间戳” 的止损条件已经触发**
`docs/02 §10` 写明：若 0.1/0.25/0.5 s 的 boundary MAE 与 event F1 无显著差异，应诚实改为 “100 ms output grid with uncertainty”。
v6k 实测四档命中率 = **0.635 / 0.688 / 0.778 / 0.900**，onset MAE 0.262 s → 0.1 s 与 0.25 s 的差异主要来自标签噪声，不是模型能力。
更根本地，`docs/22` 问题 25 指出 v6k 的 onset 记录的是**源在 mix 中的放置位置**而不是声音实际出现时间 → **标签本身错了**，当前一切时间指标都建立在错的参考上。
→ 对外表述统一改为“100 ms 输出网格 + 不确定性区间”，并**同时报 ±0.1/0.25/0.5/1.0 四档**；`0.1 s 是否成立`只能由人工标注 pilot 裁定（`docs/03 §8.3`）。

### 2.3 纪要提出但文档中不存在的新增项

| 新增项 | 评估 | 建议处置 |
|---|---|---|
| **反向应用叙事**（agentic 生成 / 精细混音 / 视频动作控制 / 精调数据供给） | 极好的 motivation 与业务对齐资产，`docs/02 §9` 摘要目前完全没有这一层 | 写进论文 intro 的 motivation 段与业务立项文档；**不能作为 contribution**，因为无任何下游实验支撑 |

### 2.4 时间预算的硬冲突

- 纪要：**一个月**周期，前两周攻数据。
- `docs/04 §8`：P0(2周) → P1(4–6周) → P2(6–10周) → P3(12–18周)；`docs/04 §9` 投稿主线 **NeurIPS 2027 / ACM MM 2027**，明确判定 ICLR 2027（2026-09-11/16 截止）不现实。

## 3. 关键研究问题（按可证伪性与当前证据状态重排）

每条给出：问题 → 当前证据 → 判定实验 → 若失败的处置。

### RQ1（最关键）声源归属是否可学？
- **问题**：模型能否把跨时间的多个事件正确归到同一持续声源（同一说话人/同一乐器轨），即 `event → track pointer`？
- **当前证据**：pointer 准确率 0.30 → 0.34（扩量后更差）。但数据 100% track↔event 双射、输出格式无 `track` 字段 → **既无训练信号，也不是有效测量**。这不是“模型学不会”，是“题目没出对”。
- **判定实验**：v7 中 ≥30% track 挂 ≥2 event、≥25% clip 含 ≥2 speaker、输出格式加 `track=`；然后在 **oracle track 与 predicted track 两种条件下分别报 pointer accuracy**（`docs/11 §10` 最低通过线）。
- **失败处置**：若 oracle track 下 pointer 也学不会，说明 MOSS 的 12.5 Hz 语义特征不含 source identity 信息 → 必须加浅层 TF evidence encoder（`docs/08 §6.2`），而不是继续加数据。

### RQ2 “0.1 s 时间精度”是否是一个真实存在的目标？
- **当前证据**：四档命中率 0.635/0.688/0.778/0.900；且 v6k 的 onset 标签定义本身错误（`docs/22` 问题 25）。
- **判定实验**：唯一途径是 200 条真实录音的人工标注 pilot，每个边界标 **earliest / best / latest**，报告标注者间 boundary MAE 作为模型上限背景（`docs/03 §8.2-8.3`）。只有模型误差接近或低于人工分歧，才能讨论 100 ms 级精度。
- **失败处置**：改称“100 ms 输出网格 + 不确定性”，主指标降级为 ±0.25 s，把 soft boundary distribution 作为贡献（`docs/02 §H4`）而非精度数字。
- **注**：这是**最长前置**任务，必须立即并行启动，不能等数据流水线修完。

### RQ3 集合式（排列不变）解码相对自回归时间戳，是否真的改善重叠？
- **当前证据**：**唯一站得住的正面证据**。高 overlap(≥0.5) 上 F1 0.714 → 0.875（+16.1pp，`docs/13 §2`）。
- **风险**：产生该增益的是“排列不变训练 + 事件计数前缀”，**不是 DETR 槽位解码器**（后者 F1 0.08–0.12，无法过拟合 32 条）。
- **判定实验**：`docs/04 §5` 第 1 行——同 backbone / 同数据 / 同参数预算，只移除 event slotter 的 AR 对照，并按并发源数分解曲线。
- **表述纪律**：论文中必须写“permutation-invariant target ordering + event-count prefix”，不能写“slot-based set prediction”。

### RQ4 局部证据约束是否降低幻觉？（三大创新之一，**未实现**）
- **当前证据**：无。S2 未实现，`docs/13 §4` 条件 3 标记 ❌。
- **判定实验**：`docs/11 §11` S2 四路对照（global only / time-mask local / TF-mask local / local+gated global）+ `docs/04 §5` 的 `no-local` 与 `unrestricted-global` 双向消融。预期：去掉局部证据 → 幻觉上升但语言更流畅；完全去掉全局 → 事实性保持但音乐描述与场景关系下降。
- **这是把“可解释性”从训练层落到可测量的唯一路径**，与纪要 §1.5 的“训练层可解释机制”直接对应。

### RQ5 CARC 反事实监督是否优于等量伪标签 SFT？（三大创新之二，**结论不确定**）
- **当前证据**：小数据上幻觉 −71%（198→57），5k 数据上退化（`docs/13 §6` 判定它当前只是**正则化工具**）。
- **判定实验**：`docs/10 §6.3` 的差分奖励闭环 + `docs/04 §5` 第 4 行（去掉 CARC 保留相同 pseudo SFT）。前置条件是**真分轨**（MUSDB18 / Slakh2100）与 audibility 门控可用——而 `audibility` 字段当前全空，`MEMORY.md` 显示 MUSDB18 已下载但**从未使用**。
- **失败处置**：`docs/02 §10` 止损线——200 条真实 pilot 上无可信增益则不扩百万数据，优先查 audibility gating / separator leakage / teacher collapse。

### RQ6 统一单模型相对专家级联，代价与收益各是多少？
- **当前证据**：已有 topline（0.948 / 0.890 / 0.270），结论是**隐式 > 显式**。
- **仍需回答**：统一训练的相互干扰有多大——speech WER 与 music caption 是否同时恶化。当前 per-type F1 = music .95 / sfx .968 / speech .952，看不出干扰，但**语音只有 ~5 个 mp3 源、无 verbatim 转录评测**，这个数字没有诊断力。
- **判定实验**：接回 LibriSpeech（270 speakers / 带转录），报 speaker-attributed cpWER（`docs/04 §3.3`）；`docs/04 §5` 单通用 adapter vs modality adapters 消融。

### RQ7 数据结构与数据量，哪个是当前瓶颈？
- **已部分回答：结构。** 事件 F1 在 1000 条真实数据上饱和于 0.970，而 pointer / 0.1 s / source-count 三项**同时恶化**。
- **判定实验**：v7（200–500 条，结构修复，不扩量）对比 v6k（1000 条，结构单一）。**预期 F1 下降属正常且期望**——任务变难了；成功标准是 pointer 与 ±0.1 s 首次“可学可测”，而不是 F1 更高。
- **这条必须写进论文的实验设计**，否则 reviewer 会把 v7 的低 F1 当作退步。

### RQ8 “可解释性”能否成为指标而不是包装？
- **问题**：纪要提出的 Clue/Claim + 置信度 + 低置信二次校验，能否产生可量化的收益？
- **判定实验**：selective risk-coverage 曲线、ECE/Brier、`docs/10 §8` 的六项因果测试（source removal / wrong-window / visual lure / language-prior / echo / low-audibility）。
- **红线**：`docs/08 §4` 要求四种运行模式**分别报告**，闭源 verifier 的收益不得算进 base model。`docs/10 §7` 的 reward hacking 表要求“全部 abstain”这种作弊被 coverage target 挡住。

### RQ9（业务侧，纪要独有）结构化时间账本能否作为下游生成的可用控制信号？
- **当前证据**：零。
- **建议**：只作 motivation。若要成为 contribution，最小验证是——用预测 ledger 驱动一次重混/重生成，评测重混音频与原音频的事件级一致性（这本质上是 CARC 的逆向使用，成本可控）。

## 4. 当前最大风险（按严重度）

1. **复现性事故已发生，且未修复**：v6k 的 1000 条音频、`/tmp/real_audio`、`/tmp/moss_weights` 全部被清空 → **最好成绩 F1 = 0.970 不可复现**（音频与源素材皆无、脚本硬编码 `/tmp`、manifest 无源溯源、`os.listdir` 顺序不保证）。`data/derived/real_mix_v6/audio/`（200 条，61 MB）是**唯一完好的真实数据**。→ 备份 + 参数化 + 记 sha256 是**第 0 优先级**，早于任何造数与训练。
2. **泄漏无法验证**：manifest 不记源路径，heldout 按索引切；speech 仅 ~5 个源文件生成 260 条 → 0.970 只证明“同素材不同随机组合”的泛化。任何对外数字都必须附上这条限定。
3. **自我验证闭环**：teacher = 底座 = 评价三者同族（§2.2 ⑤）。
4. **三大创新点全部未达成**：S2 未实现、CARC 不确定、benchmark 缺失（`docs/13 §4`）。若维持现状，论文将退化为“MOSS + 新 prompt + 更多伪标签”，`docs/02 §8` 已判定这种情况**顶会新颖性不够**。
5. **时间预算错配**：一个月 vs 12–18 周（§2.4）。
6. **两套数据流水线未打通**：包内正式渲染（有 gate、有文档、有重放 hash）与 `scripts/` 真实混合（无文档、无 argparse、硬编码 `/tmp`）并行存在。真实数据走的是后者，因此**三道 gate 全部绕过**。
7. **交接风险**：纪要中提到主导者“可能随时离开”、数据存其工作目录。→ 所有路径必须迁入工作区内持久路径，README 与流水线文档不能只存在于一个人头脑里。

## 7. 一句话总结

纪要的**思路框架与仓库方案同构**（source attribution 优先、track/event 分层、统一单模型、SFT→DPO、双层可解释性），无需推翻；但纪要把难点排序为“先扩数据规模、方法后置”，而实测证据给出的排序恰好相反——**事件 F1 已在真实数据上饱和于 0.97，0.1 s 边界与声源归属两项零进展，且这两项的失败是数据结构缺陷（track↔event 双射、零多说话人、onset 标签定义错误、audibility 全空）而非数据量不足**。因此下一步的唯一正确目标不是造更多数据，而是**造结构正确的数据、修复复现性、并立刻启动人工标注 pilot** 来裁定“0.1 s”这个核心命题是否成立。
