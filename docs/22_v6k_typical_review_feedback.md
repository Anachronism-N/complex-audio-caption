# v6k 典型样例 Review 反馈（2026-08-15）

## Review 结果

人工 review 7 个场景的典型样例后发现：**时间戳标注和 caption 准确性存在系统性问题**。

> 2026-08-16 代码复核说明：下面的听感观察仍然有效，但“混音时忽略 onset、所有
> source 都从 0 s 播放”的根因判断不成立。`build_real_mix_v6.py` 确实把每个波形
> 写入 `int(onset * sample_rate)`；0 s 听到的声音可能来自另一个 source，也可能是
> source 自身包含标签未覆盖的内容。v6 的真实标注缺陷是用“整段波形的放置区间”
> 代替“短时能量实际活跃区间”，且没有保存可重放 stems，因而无法逐源追责。新锚点
> 已改为从持久化 stem 重算 activity mask，并把它作为数据门禁。

### 问题 25：时间戳标注起始偏后
- **rv6k_0004**：一开始就有声音，但标注从 1.2s 才开始
- **rv6k_0006**：从一开始就有声音，但标注从 2.4s 才开始
- **代码复核后的根因**：
  1. onset 是源波形在 mixture 中的放置位置，旧标注没有检测源内部前后静音或多段活动
  2. 0 s 处的声音可能来自另一个已放置 source，不能只凭整段混音把它归给 1.2 s/2.4 s 的事件
  3. 旧制品没有保留可重放 stems，无法证明某段可听内容来自哪一个 source
- **影响**：模型学到的 onset 时间是**源在 mix 中的位置**，不是声音实际出现的时间
- **改进**：
  - onset 应改为**声音实际出现的相对时间**（相对 mix 起点）
  - 或者在混音时确保源 onset > 0 的部分有明确的音频对应

### 问题 26：caption 不够详细导致误判
- **rv6k_0004**：最开始就有音乐声，后来又出现一段音乐，但 caption 只描述了一个 music 源
- **根因**：
  1. MOSS 对单个源的 caption 可能不完整（漏掉部分内容）
  2. 一个 ESC-50 音频可能包含多种声音（如"女声短句"源可能实际是音乐片段）
  3. 源的 `esc50_cats` 选择可能与实际音频不匹配
- **影响**：GT caption 不完整 → 模型学到的描述也不完整
- **改进**：
  - 对每个源使用更详细的 MOSS prompt（"Describe ALL audible events"）
  - 或对每个源做分段描述

### 问题 27：音源内容与 caption 不匹配
- **rv6k_0006**：标注有"钢门撞击声"，但实际听不到
- **rv6k_0002**：有救护车鸣笛声，但标注是"火车"和"脚步"
- **根因**：
  1. ESC-50 的文件名标签可能不准确（如标注"door"但实际是其他声音）
  2. MOSS caption 基于实际音频内容，可能与文件名标签不一致
  3. 混音后某些源可能被其他源盖住，听不到
- **改进**：
  - 混音后验证每个源的实际可听性
  - 如果某源被盖住，不写入 caption

### 问题 28：人声质量仍需提升
- **rv6k_0003**：好像是男声，且两者都带有噪声，听得不是很清楚
- **根因**：
  1. 人声源（test_en.mp3, faker_and_chovy.mp3）本身可能带背景噪声
  2. 压缩和 EQ 处理可能引入噪声
  3. 音乐源如果含人声（如 GTZAN 的某些曲目）会混淆
- **改进**：
  - 使用更干净的人声源（LibriSpeech，纯净录音）
  - 人声源加载前做降噪处理
  - 验证音乐源确实是纯器乐

### 问题 29：场景组合不合理
- **rv6k_0005**（餐厅）：有蟋蟀声——餐厅不应该有蟋蟀
- **rv6k_0002**（街道）：有救护车鸣笛但标注为火车
- **根因**：ESC-50 的类别随机分配到场景模板，未验证合理性
- **改进**：
  - 场景模板限制 ESC-50 类别子集（如餐厅只用 can_opening、washing_machine 等）
  - 或用 LLM 验证场景-音源合理性

## 根因总结

v6k 的核心问题是 **时间戳和 caption 的准确性**：
```
源的 onset 是整段波形放置位置，不等于短时活动边界
→ caption 基于源音频，但混音后可能听不到
→ ESC-50 标签可能不准确
→ 场景组合可能不合理
```

## 改进方案

### 方案 S：修正时间戳
1. onset 改为**声音在 mix 中实际出现的相对时间**
2. 混音后检测每个源的实际 RMS 活跃区间
3. 用活跃区间作为 onset/offset，而非放置位置

### 方案 T：增强 caption
1. MOSS prompt 改为 "Describe ALL audible events in detail"
2. 对每个源做分段描述（如果源较长）
3. 混音后对整个 mix 运行 MOSS 作为最终 caption

### 方案 U：场景-音源合理性验证
1. 场景模板限制 ESC-50 类别子集
2. 用 LLM 验证：给定场景，判断音源是否合理
3. 不合理的组合重新采样

### 方案 V：人声质量提升
1. 下载 LibriSpeech（纯净人声+转录）
2. 人声源加载前做降噪
3. 验证音乐源是纯器乐

## 下一步行动

2. **增强 caption**：更详细的 MOSS prompt
3. **场景合理性**：限制 ESC-50 类别子集
4. **人声质量**：下载 LibriSpeech
