### 数据处理流程：两套并行且未打通

**A. 包内正式渲染流水线**（有文档、可复现）
`configs/data/*.yaml → cli/render.py → scene_graph_sampler → renderer → activity → schema.Ledger → manifests → datamodule`

- CLI：`python -m sceneledger.cli.render --config ... --output-dir ... [--limit N] [--validate]`
- 产物：`manifest.jsonl` / `data_card.md` / `listen_list.csv` / `audio/*.wav` / `audio/stems/*.wav`
- 三道校验（`manifests.py:215-266`）：同 seed 重放 hash 一致、stems 求和 == dry_mixture、ledger pydantic 校验
- 渲染顺序（`renderer.py:352-448`）：load → gain → 按类型 fade → repeat → 逐源 RIR → onset 放置 → 求和 → 背景 ambience bed(-18dB) → speech 触发 ducking(70%,2-5dB) → 场景级 echo → 削峰
- activity（`activity.py:119-182`）：10ms hop RMS → `rms > δ_act·rms_max` → OR 聚合到 0.1s → spans → 合并小间隙；music/ambience 走 `is_continuous` 低门限分支
- 已产出：tac_mini(500)、b2_no_template、b3_unified、b3_5k(5000)、b3_v2(仅 manifest)

**B. `scripts/` 真实音频混合流水线**（几乎无文档、无 argparse、硬编码 /tmp）
`download_sources.py + download_music.py → extract_sources.py + setup_esc50.py → build_real_mix_v{2,3,3b,4,5,6}.py → convert_v6_manifest.py → test_real_mix.py`
外加 `generate_review_package.py → data/review/review_50.csv`；`extract_audio.sh` 是全仓唯一接受参数的脚本（解 `audio.tar`，对 real_mix 无效）。

v2→v6 演进：v2 模板+音乐人声+ducking → v3 扩源(FMA/LibriSpeech/UrbanSound8K) → v3b 人声清晰度 → v4 分离 vocal/music → v5 caption 改为 MOSS 实听 → v6 换 GTZAN 纯器乐 + 音乐 gain 抬高 + ffmpeg 兜底 + RMS 验证。

### 关键技术问题（已核实，后续应修）

1. 两套时间戳语义不一致：A 用 RMS activity 反推；B 直接 `onset + len/sr`（`build_real_mix_v6.py:255-256`）。`docs/09:110-114` 要求的 semantic_span / evidence_span / boundary_uncertainty 均未落实。
2. `convert_v6_manifest.py:44-47` 把 hash 字段填空串 → `validate_manifest` 对真实数据完全失效。
3. `renderer.py:383-402` 背景 ambience bed 是未标注声源，评测时可能被算作漏报。
4. stems 只等于 dry_mixture；ducking 用 `mixture += stem*(duck_gain-1)`（`renderer.py:427`），stems 不同步。
5. sampler 可采样 resolution 0.5/1.0，但 `Ledger.time_resolution_sec` 是字面量 0.1（`schema.py:204`）。
6. `SourceKind`（`scene_graph_sampler.py:33`）不含 `"vocal"`，但实际大量使用。
7. `data_card` 标题硬编码 "TAC-mini"（`render.py:138`）。
8. `/tmp` 依赖导致 real_mix 200 条复现性为零；ESC-50 获取步骤在仓库中完全缺失。
9. docs/ 内检索 `build_real_mix|real_mix_v|download_sources|setup_esc50` → 0 命中（文档缺口已确认）。

### 研究方案要点

SceneLedger：混合音频 → 一次前向输出可重叠的带时间戳事件集合（`<speech>/<lys>/<music>/<sfx>`），0.1s 网格。
三大创新：① Track(8)–Event(24) 两级排列不变槽位 + event→track pointer；② evidence-first（每句话只能从自己的局部时频证据生成，时间由边界头出、不由 LLM 猜）；③ CARC 反事实重混一致性（加入/移除/平移/污染的集合代数监督 + 可听性门控）；④ WildMix-Cap 基准。
底座：MOSS-Audio-4B-Instruct + LoRA(310M)，单卡 40GB，训练 8-25 分钟。

### 进展（实验 08-09~08-11，真实混音 08-12~08-14）

合成数据链条：B0 0.000（格式失败，预期）→ B1 0.932 → B2 0.935(w=5 最优) → B3 0.902(幻觉暴涨 55→198) → B3-permuted 0.913 → B3-slot-aware 0.926 → **B3-slot-aware-5k 0.948**（幻觉 -77%）。
高 overlap(≥0.5)：B3 0.714 → permuted 0.875（**+16.1pp，最强正面证据**）。
P5：mixture 直接 caption 0.948 > oracle stems 0.890 >> Demucs 级联 0.270 → **隐式 > 显式分离**。
S1a DETR 槽位解码器 F1 仅 0.08-0.12，**连 32 样本都过拟合不了**（优化困难）。当前"槽位"实际是"输出前加一句事件计数"的廉价替代。

**v6 真实音源 50 条实测**（`reports/b3_real_v6_metrics.json`）：F1 0.865、P 0.937、**R 0.857**、onset MAE 0.300s、**±0.1s 命中率仅 58.3%**（±1.0s 才 90%）、**pointer 准确率 44.7%**、source_count MAE 1.12；music 召回最低 0.786；50 条中 3 条完全空输出。
→ 掉分主要是漏检（变保守），不是幻觉；**0.1s 精度的止损条件（docs/02:211）已触发**，应改称"100ms 输出网格 + 不确定性"。

论文 5 个最低成立条件：1、2 达成；**3(S2 局部证据) 未做、4(CARC 优于伪标签SFT) 不确定、5(benchmark) 缺失** —— 恰好是三大创新点。

重要自我否定（`docs/16`）：合成音频人耳无法辨认（语音=正弦波、5000 条音乐听起来像同一首），**0.948 只代表学到了时间结构，不代表真实能力**。

### 后续推进（尤其数据）优先级

关键认知：**real_mix v6 仍是"音源真、场景拼"，零野生录音、零人工标注。**

1. **[最高] 200 条真实录音人工标注 pilot**（`docs/07:100-112` 配额：重叠多说话人50/语音+音乐音效50/音乐+歌词40/一般复调40/恶劣声学20；双标+第三人裁决；边界标最早/最佳/最晚；150 dev + 50 test）。这是唯一无法靠算力压缩的环节，且是判断 0.1s 是否有意义的唯一参照。
2. v6 扩到 1000-5000 条前先修：GTZAN 流派标签噪声、纯器乐来源太窄(改用 MUSDB18 accompaniment)、**歌词轨完全空缺**、逐源 caption 太单薄；统一三套时间定义。
3. CARC 最小闭环：先用真分轨(MUSDB18/Slakh2100)验证损失有效 → 再上 5k-10k 真实片段(WhisperX/pyannote/Demucs/MOSS/FLAM) → 残留泄漏人工抽检(四重门槛) → 对比同量伪标签 SFT → go/no-go 才扩 50k-100k。
4. WildMix-Cap：200 dev + 800 hidden test；pilot 不进最终 test；测试集不过伪标签流水线；按源视频/上传者/指纹/歌曲分组切分。

模型侧：① 实现 S2 局部证据（浅层 TF encoder + track mask + 对比损失，做 no-local / unrestricted-global 消融）；② 修 DETR 槽位或诚实说明当前是训练时打乱顺序实现；③ 修正 0.1s 表述。

三个警惕点：① 伪标签/底座/评价都是 MOSS → 自我验证闭环，需引入结构不同的验证信号；② "变保守"不等于"变好"，P/R 必须同时报；③ 合成分数定位为格式验证。

投稿：ICLR 2027(09-11/09-16) 不现实；主线 NeurIPS 2027 / ACM MM 2027。
