## 任务1：会议纪要（nzc × yikaihuang）与既有研究方案的对齐分析

产出文档：`docs/23_meeting_alignment_and_key_questions.md`。

### 纪要中值得长期保留的增量（文档此前完全没有）

1. **反向应用叙事**：精准时间戳作为下游生成的控制信号——agentic 音频生成、多音轨精细混合、视频动作控制、精调数据自动供给；定位"万金油前置数据能力"，生成/理解/交互三组通用。→ 只能作论文 intro 的 motivation，不能作 contribution（零下游实验）。
2. **Clue / Claim + 0–1 置信度 + 低置信触发二次校验**：与 `docs/10 §6.2 R_cal`、`docs/04 §3.5` selective risk-coverage 天然对应，是**唯一能把"可解释性"从修辞变成可测指标**的抓手。建议 Claim 定义为 `(event_id, type, span, evidence_score, confidence)`，用 ECE/Brier + risk-coverage 评测。
3. **RAG 层级化声音语料库**检索匹配环境音（针对"纯环境音无韵律、极难识别"）。→ 与 evidence-first 有张力，只能降级为教师侧 candidate proposer（`docs/08 §5.2`），不得直接成为正标签。
4. **场景-音源合理性用 LLM 校验**（呼应 `docs/22` 方案 U）。
5. 纪要明确：**场景层只用于规则设定与数据构造，不作为模型输入**；动态时域变化（走近瀑布/室内到室外）当前搁置。

### 纪要与实测证据冲突、需纠偏的 6 条

1. "每轨生成 caption" ≠ 推理时显式分轨级联（已实测 0.948 / 0.890 / 0.270，隐式 > 显式）；per-track 只是标注与表示层。
2. "recaption + 规则/LM 拼接" 就是 TAC-style 合成，其 0.948 已被 `docs/16` 自我否定；200 条真实(0.967) > 5000 条合成(0.948)。
3. "核心矛盾从数据够不够转向怎么拼" → 正确表述是**结构 > 数量**（1000 条真实使 F1 饱和 0.970，但 ±0.1s 0.842→0.635、pointer 0.30→0.34、source_count 0.95→1.14 同时恶化）。
4. "把层级定义为 query 学习" 已试过失败（S1a F1 0.08–0.12，32 条都过拟合不了）；当前 slot-aware 只是事件计数前缀，论文表述须改为 "permutation-invariant target ordering + event-count prefix"。
5. "互联网数据全靠大模型打标" 触发自我验证闭环（teacher=底座=评价同族）。
6. "精准时间戳" 止损条件已触发，且 **v6k 的 onset 标签定义本身是错的**（`docs/22` 问题 25：onset 记的是源在 mix 中的放置位置，不是声音实际出现时间）→ **在人工 pilot 出来前，所有时间指标只有相对比较价值，无绝对意义**。

### 时间预算硬冲突
纪要一个月（前两周攻数据）vs `docs/04 §8` 的 12–18 周 + NeurIPS/ACM MM 2027。→ 结论：必须显式双轨（轨 A 业务交付/数据底座 4 周；轨 B 论文主线 12–18 周并行，人工标注 pilot 立即启动因其为最长前置）。
